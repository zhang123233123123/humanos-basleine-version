一个任务的
进程生命周期

自然语言输入相当于系统调用。内核先创建任务对象和 PCB，再进入 Ready Queue；调度器分配合法时间片，用户确认后由 Dispatcher 发布到正式日历并等待执行。

01 / SYSTEM CALL

接收用户命令

区分 CREATE、UPDATE、DELETE、QUERY、INTERRUPT 与 RESCHEDULE。

02 / FORK

创建 Process

AI 将自然语言编译为 Task：时长、Deadline、Priority、Load 和 Dependency。

03 / PCB

持久化上下文

先保存 Process Control Block；AI 排程超时也不会丢失任务。

04 / RESOURCE MAP

扫描可用资源

把一周 CPU 时间、固定事项、已有 Session 与可用窗口映射为 Slot。

05 / TIME SLICE

切分时间片

按 Profile 的专注与休息周期，把总工作量拆成可执行时间片。

06 / READY QUEUE

候选进程入队

合法任务进入 Ready Queue，再按优先级、状态适配度和切换成本排序。

07 / SCHEDULER

验证调度结果

检查资源冲突、Deadline、Dependency、工作量守恒和并行上限。

08 / DISPATCH

分派并等待运行

用户确认后生成 Plan Revision 与 Execution Session，进入 Planned 状态。

Interrupt Handler
中断处理程序

用户中断不是暂停前端计时器，而是触发内核事件：保存 PCB、更新 Process State、决定 Waiting、Suspended 或 Ready，并在资源受影响时调用 Rescheduler。

用户动作
调度概念
HumanOS 系统行为
点击 Pause
Interrupt
停止有效计时，原子保存 task_id、actual duration、remaining work、Session、Plan Revision 和执行上下文。
短暂休息
Timed Waiting
任务保持不变并进入定时等待；休息结束后恢复同一任务，优先由 Session 余量或 Buffer 吸收。
晚些继续
Suspension
释放当前时间片，保存 Progress、Next Step 和剩余分钟；到选择的时间重新进入 Ready Queue。
切换任务
Preemption + Context Switch
保存当前任务上下文，从 Ready Queue 选择另一任务直接执行，并计算切换是否影响未来日程。
帮助我决定
Scheduler Decision
调度器综合当前状态、任务优先级、Deadline、Fixed Event、Buffer 和剩余容量提出具体动作。
恢复任务
Resume / Dispatch
通过 Resume Brief 恢复上下文，重新检查 Ready 条件和后续冲突，再决定直接运行或生成局部调整草案。
影响后续安排
Rescheduling
保护已执行 Session 和 Fixed Event，只释放受影响的未来 Slot；用户确认 Calendar Diff 后创建新 Plan Revision。

HumanOS 的
内核数据结构

这些对象共同承担传统操作系统中资源表、进程描述符、调度版本和执行上下文的职责，并保证所有页面读取同一个后端事实源。

Profile / Resource Table

描述可用时间、专注周期、休息长度、人的容量与已确认 Pattern。

Task / Process

描述目标、Deadline、Priority、Load、Dependency 与 remaining work。

PlanRevision / Schedule

保存调度表版本、局部 Calendar Diff、变更原因与回滚边界。

Session / PCB Context

保存时间片、实际运行时间、暂停记录、进度、Next Step 与状态。
