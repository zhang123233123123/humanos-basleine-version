# HumanOS 访谈候选主题 v0.1

## 1. 当前分析位置

本文档基于93条开放编码记录、13个聚焦类别及《聚焦编码全量审计》生成候选主题。主题是跨记录的意义模式，不是类别名称的改写，也不是系统需求清单。

当前版本仍属于主题搜索阶段。四个主题只有通过逐条回查、主题间区分和反例审查后，才能成为最终分析主题。本阶段不使用 JITAI 预设构造重新编码材料。

证据缩写：E 为真实事件，S 为真实事件后的自我报告，R 为一般经验，H 为假设性回答，G 为访谈者强引导后的回答。

## 2. 候选主题总览

| 候选主题 | 中心组织概念 | 主要聚焦类别 | 当前证据基础 |
|---|---|---|---|
| CT1 原计划在可行性重新评估中失效 | 人们不是单纯“偏离计划”，而是在外部条件、自报状态和任务反馈变化后重新判断任务能否继续 | FC01、FC02、FC03、FC04、FC05 | E、S、R；真实事件基础较强 |
| CT2 计划修复是跨时间尺度的重新分配 | 继续、切换、延期和重排把一次变化传播到同日、次日、下一周或项目后续阶段 | FC05、FC06、FC07，辅以 FC01、FC02 | E、S、R；另有少量 G，必须分开 |
| CT3 返回任务需要重建足够的任务上下文 | 恢复不是统一计时问题，而是重新找到位置、推理、材料与下一步；已有痕迹和主动检查点承担不同作用 | FC08、FC09、FC10，辅以 FC06、FC12 | E、R 与大量 H；实际痕迹和假设方案必须分层 |
| CT4 支持的正当性取决于必要性、负担、控制与场景匹配 | 有些人需要重新定向，有些人依靠自然边界或既有结构即可继续；记录和提示不能被默认强制 | FC11、FC12、FC13，辅以 FC08、FC09、FC10 | R、H、少量 E/G；主要作为边界与设计警示 |

四个主题形成一条候选分析链：

```text
条件、状态或反馈变化
→ 重新判断任务可行性（CT1）
→ 继续、切换或重排，并产生下游影响（CT2）
→ 返回时重建任务上下文（CT3）
→ 决定是否值得提供、记录或接受额外支持（CT4）
```

这条链不是所有参与者都经历的固定阶段，也不表示因果顺序已经得到验证。

## 3. CT1 原计划在可行性重新评估中失效

### 3.1 中心组织概念

材料中的计划变化通常不只是“自控失败”。外部条件、参与者明确报告的状态和任务自身反馈改变了任务的可执行性，人们据此选择不开始、继续、暂停或停止。这个主题把“发生了什么变化”“参与者如何判断”和“是否继续”连接起来，但不把自报状态当作系统可直接观测的客观事实。

### 3.2 支持材料

| 证据 | 例子 | 支持的关系 |
|---|---|---|
| E：P03 | 网络中断、替代地点营业时间有限，只能完成可执行部分并把剩余工作延期 | 外部资源改变可行范围 |
| E：P07 | 导师、设备、样品和数据结果连续改变研究阶段能否推进 | 外部约束与任务反馈共同改变计划 |
| E+S：P10 | 实际词汇完成量低于计划，自报状态和记忆表现不佳，参与者延长任务 | 计划预期、任务结果和自报状态共同进入继续决定 |
| E+S：P13 | 炎热环境、防护装备、疼痛及参与者判断的安全和结果风险使实验移至晚上 | 身体状态、环境和任务风险共同改变可执行性 |
| R：P04、P05、P12 | 情绪、失败、设备故障或软件学习受阻与停止/延期相连 | 一般经验中也存在条件性停止，但不是单次事件效果 |

参与者覆盖重点包括 P01、P03、P04、P05、P07、P09、P10、P11、P12、P13。

### 3.3 反例与张力

- P14 表示紧迫任务临近截止时可能继续，不会仅因当下情绪停止；状态不是绝对决策规则。
- P10 在表现低于计划后延长任务，而 P12 在非紧急任务状态不佳时停止；同类信号可以通向相反行动。
- P01 的家庭接待和 P02 的假期低执行包含“未开始”，不能都称为执行中断。

### 3.4 当前可主张与不可主张

可以主张：参与者描述的任务可行性同时受到资源、明确自报状态和任务反馈影响，继续/停止决定具有条件性。

不能主张：系统已经能够准确识别状态；某一种状态必然导致停止；计划偏离主要由情绪或意志力造成。

## 4. CT2 计划修复是跨时间尺度的重新分配

### 4.1 中心组织概念

原安排失效后，人们不只在“做或不做”之间选择。他们会继续可执行部分、改做其他任务、顺延未完成内容、重建计划或压缩后续阶段。一次变化可能停留在当前时段，也可能传播到同日其他任务、次日、下一周或长线项目。

### 4.2 支持材料

| 证据 | 例子 | 时间尺度与修复方式 |
|---|---|---|
| E：P03 | 先在替代地点继续可执行部分，再按资源恢复情况延期剩余工作 | 小时至次日；部分继续与延期 |
| E：P09 | 白天事务推迟学习，利用零散时间继续，未完成内容又阻止次日复盘并顺延至下周 | 时段至跨周；继续与依赖传播 |
| E：P13 | 阅读提前、实验移至晚上、数据获取与分析推迟 | 同日；任务交换与整体重排 |
| E：P07 | 导师讨论、设备预约、样品、数据分析和写作形成串行传播 | 数周；阶段回退与下游压缩 |
| R：P02、P04、P05、P12 | 任务顺延、切换到偏好任务、停止当天工作或连续延期 | 日常经验；不同修复策略 |

参与者覆盖重点包括 P01、P02、P03、P04、P05、P07、P09、P10、P12、P13。

### 4.3 反例与张力

- P01 在中断后直接处理积压任务，没有报告复杂重排。
- P08 的社交活动取消后没有恢复窗口；不是所有失效计划都会被修复。
- P14 会在开始前依据可用时间选择文献，以减少中途暂停；有时策略是预防而不是事后重排。
- 任务切换可能让工作继续，也可能像 P11、P12、P13 所述造成多次切换、沉浸替代活动或返回困难。

### 4.4 当前可主张与不可主张

可以主张：材料呈现多种时间尺度的计划修复，且任务依赖会使局部变化传播到后续安排。

不能主张：自动重排一定改善完成情况；所有短时中断都会产生长期传播；系统应当把所有任务向后平移。

## 5. CT3 返回任务需要重建足够的任务上下文

### 5.1 中心组织概念

参与者返回任务时需要恢复的并不只是“当前任务名称”。他们可能需要找到停止位置、回忆已经尝试的路线、重读材料、恢复推理背景或确认下一步。恢复成本取决于任务类型、切换后的注意转移，以及任务本身是否留下了足够痕迹。

### 5.2 实际返回与既有痕迹

| 证据 | 例子 | 上下文作用 |
|---|---|---|
| E：P07 | 回看项目文件夹、既有文献和导师讨论记录 | 恢复材料位置和项目背景 |
| E：P09 | 使用已有标记避免从头整理，报告返回约需10至15分钟 | 既有标记支持定位，但仍有恢复耗时 |
| E：P10 | 软件保存词汇进度，参与者查看后直接继续 | 持久化进度降低定位成本 |
| E：P11 | 返回困难阅读后仍不想继续，随后因时间压力继续并重新判断难度 | 返回包含动机、重读和任务反馈，而非单一定位动作 |
| R：P04、P06、P14 | 颜色标记、阅读笔记、已有文本和写作框架支持衔接 | 自然产生或主动留下的痕迹可支持不同任务 |
| R：P05、P12、P13 | 遗忘失败尝试、沉浸替代活动、文字生成困难 | 痕迹不足或注意转移时恢复成本增加 |

实际返回相关材料覆盖 P01、P02、P04、P05、P06、P07、P09、P10、P11、P12、P13、P14。

### 5.3 假设性检查点材料

P05、P10、P11、P12、P13 以及强引导情境中的 P08 提出了可能记录的内容，包括：

- 当前步骤或停止位置；
- 已完成进度和剩余部分；
- 已尝试路线、结果与遇到的问题；
- 关键观点、摘要或推理；
- 返回后的第一个行动。

这些 H/G 材料说明“参与者在被问及时认为哪些内容可能有用”，不说明他们会主动持续填写，也不证明记录能够缩短恢复时间。

### 5.4 反例与张力

- P01 直接返回积压任务，没有显式恢复准备。
- P02 在自然子任务边界暂停，并利用可见计算结果继续。
- P06 通常自评可顺畅返回，但低投入阅读后仍需要重读。
- P10 和 P14 依靠软件进度或既有文本，而不是新增的中断表单。

### 5.5 当前可主张与不可主张

可以主张：不同任务的重新进入需要恢复不同种类的上下文；已有任务痕迹可能承担定位与提示作用。

不能主张：统一的“原因—进度—下一步”模板已经得到验证；恢复耗时能由任务痕迹单独解释；新增检查点必然优于既有软件或文档状态。

## 6. CT4 支持的正当性取决于必要性、负担、控制与场景匹配

### 6.1 中心组织概念

额外支持不是天然有益。参与者一方面描述了返回困难和可能有用的检查点，另一方面也报告自然边界、直接继续、隐私担忧、记录负担和对目标人群的质疑。候选主题因此关注“系统何时有理由介入，以及用户如何保留控制”，而不是把每次偏离都转化为强制记录或提示。

### 6.2 支持材料

| 证据 | 例子 | 边界含义 |
|---|---|---|
| R：P06 | 不愿书面保存私人决心，担心他人看到 | 信息可见性和隐私边界 |
| H：P11 | 时间紧张时只愿记录关键信息，认为完整反思耗时 | 输入负担和最小记录原则 |
| H：P12 | 不愿记录负面停止原因，担心重看影响情绪 | 反思内容并非越完整越好 |
| E/R：P01、P02、P10、P14 | 直接返回、自然边界、软件进度和已有文本已足够 | 有些场景不需要新增支持 |
| R：P14 | 质疑当前研究对象匹配，指出备考、科研和应急工作时间结构不同 | 人群和任务尺度限制系统适用性 |
| G：P08 | 作业恢复耗时和记录建议来自访谈者提供的情境 | 协议引导限制需求证据强度 |

相关边界材料主要来自 P01、P02、P05、P06、P08、P10、P11、P12、P13、P14，但各人的边界内容并不相同。

### 6.3 反例与张力

- P05 忘记既往操作和失败尝试，说明部分复杂任务可能确实需要比自然痕迹更丰富的支持。
- P09、P11、P12、P13 报告不同形式的恢复成本，不能因低需求反例而否认支持机会。
- FC11 仅涉及4名参与者且多数为 H，不能把具体隐私或负担偏好推广到全部用户。

### 6.4 当前可主张与不可主张

可以主张：材料支持可跳过、最小化和任务敏感的设计方向，并要求把既有痕迹、额外记录与用户控制区分开。

不能主张：参与者已经接受某个具体交互；系统应根据推断的情绪自动介入；所有目标人群共享相同记录负担和隐私边界。

## 7. 主题间区分

| 边界 | 区分规则 |
|---|---|
| CT1 与 CT2 | CT1 解释为什么原任务被重新判断；CT2 解释判断后如何重新分配工作及其传播。 |
| CT2 与 CT3 | CT2 关注日程和任务组合的修复；CT3 关注返回某项任务时如何恢复其内部上下文。 |
| CT3 与 CT4 | CT3 解释恢复需要什么信息；CT4 判断额外收集或提示这些信息是否必要、可接受和适用。 |
| CT1 与 CT4 | CT1 中的状态是参与者报告的决策条件；CT4 限制系统能否据此自动推断或介入。 |

## 8. 候选主题的当前判断

四个候选主题具有不同的中心组织概念，能够容纳正例和反例，也能共同解释从计划失效到重新进入的过程。当前未发现需要把某个聚焦类别直接提升为独立主题的依据。

但 CT4 的直接经验材料相对分散，包含较多 H/G 和研究边界意见。主题审查时需要决定：

1. CT4 是否作为独立分析主题保留；或
2. 将其改为贯穿 CT1–CT3 的设计边界与反思层。

在完成逐记录主题矩阵前，不将任何候选主题写成最终 findings。

## 9. 下一步

下一步建立“93条记录 × 候选主题”的主题审查矩阵，检查：

1. 每个主题内部材料是否围绕同一中心概念；
2. 同一记录是否被不必要地放入多个主题；
3. 每个主题是否同时有支持材料和反例；
4. 主题是否过度依赖 H/G；
5. CT4 应作为独立主题还是跨主题边界层。

完成主题审查后，才定义、命名最终主题，并在随后单独使用 JITAI 进行理论对照。
