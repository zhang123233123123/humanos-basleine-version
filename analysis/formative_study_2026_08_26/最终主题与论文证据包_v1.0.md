# HumanOS 访谈最终主题与论文证据包 v1.0

## 1. 分析状态

本文档完成 Braun 与 Clarke 主题分析流程中的主题定义和命名阶段。三个最终主题来自开放编码、聚焦编码、全量审计、候选主题和93条记录主题矩阵，不是把预设系统功能或 JITAI 构造套入资料。

“最终”表示当前资料集内的主题结构已经完成审查，不表示理论饱和、统计代表性或系统效果已经得到验证。后续若补充参与者或重新核对逐字稿，主题仍可修订。

## 2. 证据等级

本证据等级只用于约束论文措辞，不把质性材料转换成统计置信度。

| 等级 | 材料性质 | 允许用途 |
|---|---|---|
| L1 具体经验 | 有具体任务、变化和结果锚点的真实事件 E | 支撑“参与者经历了什么过程” |
| L2 经验性解释 | 真实事件后的自我报告 S，或参与者对反复经验的概括 R | 支撑参与者如何理解、判断或通常处理，但不当作客观测量 |
| L3 引出性材料 | 假设性回答 H 或访谈者强引导后的回答 G | 形成设计设想、问题和边界，不能写成已发生行为、稳定需求或效果 |

主题整体证据判断：

| 分析结论 | 当前判断 | 理由 |
|---|---|---|
| T1：可行性重判过程存在 | 较强的资料内支持 | 多名参与者提供 L1 事件，并有 L2 解释补充 |
| T2：计划修复跨越不同时间尺度 | 较强但异质的资料内支持 | 有日内、跨日、跨周和项目级 L1/L2；不同尺度不能合并成同一机制 |
| T3：返回涉及任务上下文重建 | 中等的资料内支持 | 有实际返回和既有痕迹的 L1/L2，但具体检查点内容大量来自 L3 |
| 固定检查点模板会改善恢复 | 有限证据，不成立为发现 | 没有实际部署或效果比较，主要是 H/G |
| 跨主题边界层 | 中等至有限的边界证据 | 低需求反例有 L1/L2；隐私、负担和协议边界较稀疏或含 L3 |

“较强”“中等”“有限”均指本资料集内部的支持结构，不代表总体效应大小。

## 3. 最终主题结构

```text
T1 从计划承诺到可行性重判
   条件、状态和任务反馈改变“现在能否继续”的判断

T2 从局部应对到跨尺度计划修复
   继续、切换、延期和依赖传播重新分配工作

T3 从返回任务到重建工作上下文
   人们利用位置、材料、推理和下一步重新进入任务

跨主题设计边界层
   必要性 × 最小负担 × 用户控制 × 场景匹配 × 证据强度
```

该顺序用于组织论文叙事，不是固定阶段模型或已验证的因果链。

## 4. T1 从计划承诺到可行性重判

### 4.1 定义

参与者原先对任务时长、数量、截止时间或阶段作出计划承诺；当外部条件、明确自报状态或任务反馈变化时，他们重新判断任务在当下是否可执行，并据此选择开始、继续、延长、暂停或停止。

### 4.2 中心组织概念

计划偏离不是单一的“没有按计划做”，而是参与者在变化条件下重新判断当前任务的可行性。这个主题关注判断依据及其与继续决定的关系，不主张系统已经能够自动测量这些依据。

### 4.3 纳入与排除

纳入：计划预期、资源和时间窗口、参与者明确自报状态、任务难度或结果反馈，以及是否继续的决定。

排除：决定后如何重排日程归入 T2；返回任务时如何找回位置和思路归入 T3；未经参与者表达的情绪或能力推断不纳入。

### 4.4 子主题

1. **外部条件改变任务可执行范围**：家庭事务、网络、人员、设备、地点和环境改变原任务能否开始或推进。
2. **自报状态成为条件性决策输入**：疲劳、疼痛、烦躁、兴趣和注意被参与者用于解释继续、延后或停止。
3. **任务反馈修正原有预期**：实际进展、失败、难度和结果风险使原时长或推进方式失效。
4. **相似信号可以通向相反决定**：参与者可能停止、切换，也可能因截止时间或积压风险继续。

|---|---|---|---|

| P07-E01，00:16:18–00:20:11 | L1 | 导师、设备、样品和数据结果先后改变项目阶段能否推进 | 展示资源与任务反馈共同改变可行性 |

### 4.6 反例和负面案例

- P14-R01（00:07:42–00:08:15，L2）：临近截止时会优先继续紧迫任务，不因当下情绪直接停止。
- P10-E01（00:10:27–00:11:04，L1）：状态和表现不如预期后仍选择继续。
- P01-E01 与 P02-R01：部分材料属于任务未开始或长期计划执行不足，不能称为执行中的突然中断。

### 4.7 论文最小主张

> 参与者描述的计划偏离经常伴随对任务可行性的重新判断；外部条件、参与者明确报告的当下状态和任务反馈共同构成判断依据，而继续、延后或停止并不由任何单一信号决定。

不可写成：HumanOS 能准确感知用户状态；疲劳会导致任务停止；系统应在检测到负面状态时自动重排。

## 5. T2 从局部应对到跨尺度计划修复

### 5.1 定义

原安排被重新判断后，参与者通过继续可执行部分、切换任务、顺延内容、重建计划或调整后续阶段来分配剩余工作。局部变化可能只影响当前时段，也可能通过任务依赖传播到次日、下一周或长线项目。

### 5.2 中心组织概念

计划修复不是简单地把一项任务向后移动，而是在剩余工作、可用时间、截止时间、替代活动和任务依赖之间重新分配工作。主题强调时间尺度和依赖结构的差异。

### 5.3 纳入与排除

纳入：部分继续、任务切换、同日重排、跨日/跨周顺延、阶段回退、后续时间压缩和任务依赖传播。

排除：导致原判断变化的状态和反馈本身归入 T1；返回某项任务时的内部材料定位归入 T3；没有证据的自动优化效果不纳入。

### 5.4 子主题

1. **局部继续与替代活动**：保留可执行部分，或切换到另一项任务、休息或娱乐。
2. **同日和跨日重新分配**：把任务移至晚上、次日或下一周期，并重新考虑剩余工作与截止时间。
3. **依赖使局部变化向下游传播**：前序任务未完成会阻止复盘、设备使用、分析或写作。
4. **修复也可能被预防或放弃**：有些人事前选择可在时间窗口内完成的任务，有些被取消活动没有恢复窗口。

### 5.5 代表证据

| 来源位置 | 等级 | 匿名化证据摘要 | 时间尺度与作用 |
|---|---|---|---|
| P03-E01，约00:19:47–00:20:26 | L1 | 先完成可执行部分，再依据资源恢复情况延期剩余工作 | 小时至次日；局部继续与延期 |
| P09-E01，00:18:24–00:20:24 | L1+L2 | 未完成学习阻止次日复盘并顺延至下一周，参与者按剩余工作量、可用时间和截止时间重排 | 跨日与跨周；依赖传播 |
| P13-E01，00:14:47–00:15:35 | L1 | 阅读提前、实验移至晚上、数据获取与分析推迟 | 同日；任务交换与整体重排 |
| P07-E01，00:14:19–00:20:11 | L1 | 讨论延期影响设备，样品和数据反馈导致阶段回退，后续写作时间被压缩 | 数周；串行项目传播 |
| P04-C02，00:19:00–00:19:29 | L2 | 未完成步骤顺延至次日，并阻止依赖它的后续任务 | 日常经验中的任务依赖 |
| P11-R01，00:15:38–00:17:16 | L2 | 困难时连续切换任务，单次切换有时可继续，多次切换仍可能失败 | 切换既是应对，也可能失效 |

### 5.6 反例和负面案例

- P01-E01（00:11:28–00:11:53，L1）：直接返回积压任务，没有复杂重排。
- P08-E01/E02（L1）：取消的社交或社团活动没有恢复窗口；并非所有变化都进入计划修复。
- P14-R03（00:10:27–00:11:30，L2）：通过开始前匹配可用时间和文献长度，尽量避免中途暂停，体现事前预防。
- P12-R03 与 P13-R01（L2）：切换或沉浸替代活动可能增加返回成本。

### 5.7 论文最小主张

> 参与者通过继续、切换、延期和重新规划来修复失效安排；这些调整跨越从当前时段到长线项目的不同尺度，并可能通过任务依赖改变后续工作，而不是表现为统一的“向后平移”。

不可写成：自动重排必然改善完成情况；任务切换是一贯有效的恢复策略；所有局部变化都会传播到整个计划。

## 6. T3 从返回任务到重建工作上下文

### 6.1 定义

返回任务时，参与者可能需要重新找到停止位置、恢复任务背景、回忆尝试过的路线、重读材料、重建推理或确认下一步。既有软件状态、文本和标记，以及参与者主动留下的记录，提供了不同强度的上下文支持。

### 6.2 中心组织概念

恢复成本取决于是否存在“足够继续”的任务上下文，而不只是离开了多长时间。已有任务痕迹与额外检查点必须分开：前者在部分实际事件中已经存在，后者很多来自访谈中被要求设想的方案。

### 6.3 纳入与排除

纳入：停止位置、材料定位、已有进度、推理背景、失败路线、下一步、重读、返回耗时和能否继续。

排除：宏观日程重新分配归入 T2；未实际使用的检查点不能作为恢复效果；没有参与者报告时不推断认知状态。

### 6.4 子主题

1. **已有任务痕迹支持重新定位**：软件进度、文本、页码、标记、文件夹和讨论记录保存任务状态。
2. **复杂任务需要恢复推理而不只是位置**：失败尝试、项目背景和写作思路可能在切换后丢失。
3. **主动检查点提出更丰富的上下文内容**：进度、问题、已尝试路线、摘要和第一个行动被参与者认为可能有用。
4. **恢复需求高度不均**：有人需要重读和梳理，也有人直接继续或在自然边界暂停。

### 6.7 反例和负面案例

- P01-E01（00:11:28–00:11:53，L1）：没有复盘或衔接，直接处理积压任务。
- P02-C01（00:12:41–00:13:45，L2）：在自然子任务边界暂停，可见计算结果直接提示下一步。
- P06-R01（00:11:10–00:12:27，L2）：通常自评可以顺畅返回，但低投入阅读后仍可能内容断片并需要重读。
- P10 和 P14：软件或已有文本已经提供足够上下文，新增表单未必必要。

### 6.8 论文最小主张

> 返回任务所需的支持随任务而异：一些参与者利用软件进度、文本、标记或项目材料重新定位，另一些复杂任务还需要恢复先前推理、失败尝试和下一步；但访谈中提出的固定检查点内容尚未经过实际使用验证。

不可写成：恢复由统一的原因—进度—下一步模板解决；检查点会缩短恢复时间；新增记录优于任务本身已有的状态痕迹。

## 7. 跨主题设计边界层

该边界层不是第四个经验主题，而是约束 T1–T3 如何转化为系统设计和论文讨论。

| 边界 | 资料依据 | 对系统解释的限制 |
|---|---|---|
| 必要性 | P01、P02、P06、P10、P14 存在直接返回、自然边界或已有痕迹足够的情况 | 不把每次偏离都视为需要干预 |
| 最小负担 | P11-H02 认为完整反思耗时；P12-H02 不愿记录负面原因 | 输入应最小化，但当前多为 L3，不能声称已验证 |
| 用户控制与隐私 | P06-C01 不愿书面保存私人决心并担心他人看到 | 记录内容、保存与提示应允许跳过和控制可见性 |
| 任务与人群匹配 | P14-C01 区分备考、科研和应急工作；P08 核心事件适配有限 | 不把同一流程推广到所有任务和群体 |
| 协议证据强度 | P08-G01 的作业中断与记录建议由访谈者强引导 | G 只能作为协议反思或设计设想，不能作为自发需求 |

边界层也保留相反证据：P05、P11、P12、P13 的恢复困难说明不能因低需求案例而取消所有支持。合理结论是支持需要可选择和任务敏感，而不是“总要介入”或“从不介入”。

## 8. 可用于 Findings 的结构

建议按以下顺序组织 findings：

1. **T1：计划如何在变化条件下被重新判断**——用 P03、P10、P13 的事件对比，加入 P14 的反例。
2. **T2：判断如何转化为不同尺度的修复**——对比 P13 的日内重排、P09 的跨周传播和 P07 的项目级传播。
3. **T3：返回为何需要不同粒度的上下文**——对比 P10 的软件进度、P05 的过程遗忘和 P14 的既有文本。
4. **跨主题边界**——集中说明低需求、负担、隐私、目标人群和强引导限制，不将其包装成第四个行为过程。

每节应至少包含一个 L1 具体事件、一个 L2 解释或对比案例，以及一个反例。L3 只应以“参与者在被要求设想时提出……”的形式出现。

## 9. 引文使用规则

本文档中的证据摘要都是分析性转述，不是可直接加引号的逐字引文。正式论文写作前必须：

1. 按参与者、记录编号和时间戳返回匿名化逐字稿；
2. 核对说话者、上下文和转录准确性；
3. 选择能够支持主题而非只复述事实的短引文；
4. 避免包含姓名、机构、地点或可识别项目细节；
5. 让反例也进入正文，而不是只留在限制部分。

## 10. 下一步理论对照边界

三个主题现在可以与 JITAI 等框架进行理论对照，但理论只能用于解释和比较：

- 哪些资料可被理解为潜在的决策点或介入机会；
