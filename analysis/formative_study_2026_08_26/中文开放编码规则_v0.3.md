# HumanOS 访谈中文开放编码规则 v0.3

## 1. 当前分析阶段

本规则只适用于“开放编码”。目标是把逐字稿中的具体事件、行为、条件、结果和明确自报转换成可追溯的中文描述性标签。

本阶段不进行以下工作：

- 不合并聚焦类别；
- 不生成候选主题；
- 不套用 JITAI 构件；
- 不提出 HumanOS 功能要求；
- 不判断某项系统机制是否有效。

## 2. 一行记录什么

一行对应一个能够被独立理解和编码的“意义片段”，而不是机械对应一句话。

满足以下任一条件时，可以新建一行：

- 任务或计划发生变化；
- 出现新的触发条件；
- 参与者采取新的行动；
- 任务出现新的结果；
- 参与者明确报告感受或身体状态；
- 出现新的恢复方式或恢复困难；
- 证据性质发生变化，例如从真实经历转入一般经验或假设回答。

同一句话包含多个紧密相关的意义时可以设置多个初始编码；如果其中包含不同阶段、不同任务或不同证据类型，则拆成多行。

## 3. 记录字段

| 字段 | 填写规则 |
|---|---|
| 参与者编号 | 只使用 P01–P14，不记录姓名。 |
| 记录编号 | 有边界的具体事件使用 `Pxx-E01`；反复发生的一般经验使用 `Pxx-R01`；相关背景使用 `Pxx-C01`；假设性回答使用 `Pxx-H01`；访谈者提供核心情境后得到的回答使用 `Pxx-G01`。编号表示材料性质，不表示证据价值高低。 |
| 时间戳 | 使用逐字稿中的开始和结束时间；无法精确定位时使用“约”，不得伪造秒数。 |
| 匿名化证据摘要 | 忠实转述片段，不复制可识别信息，不加入系统建议。 |
| 证据类型 | 从本规则第4节选择。 |
| 初始编码 | 使用具体、简短、接近材料的中文标签；多个编码用分号分隔。 |
| 分析备忘录 | 记录歧义、缺失结果、访谈者引导、边界情况及禁止推断的内容。 |

## 4. 证据类型

### 4.1 真实事件

参与者讲述了一次亲身经历。判为真实事件时，材料至少应支持以下四项中的三项：

- 可以识别的具体任务或计划；
- 可以识别的触发或变化；
- 参与者在该次经历中的行动；
- 该次经历的结果或访谈时状态。

同时，叙述中应存在“那一次、上周、当天、最近一次”等情境锚点，或者其他足以将它和日常习惯区分开的细节。没有精确日期不妨碍判定，但只有“通常、经常、我会”而没有单次经历边界时，归入一般经验。

### 4.2 真实事件后的自我报告

参与者明确报告该事件中的感受、身体状态、判断或主观评价。只记录为自报，不转换成客观诊断或绩效结论。

### 4.3 一般经验

参与者描述经常、通常或可能发生的行为模式，但没有清楚的单次事件边界。一般经验可以揭示重要行为和边界条件，但不能在报告中被改写成一次已经完整发生的关键事件。

### 4.4 假设性回答

参与者回答“如果有一个系统”“你希望系统如何帮助”等设想问题。该类材料可在后续分析偏好，但不能证明真实使用、接受度或效果。

### 4.5 访谈者总结或引导

访谈者对参与者答案的复述、推断或给出的例子。它本身不作为参与者证据；只有参与者随后明确确认、修正或展开的内容才能编码，并在备忘录中保留引导痕迹。

如果具体任务、触发、返回过程等核心事件结构主要由访谈者提供，参与者只确认或补充部分内容，则使用 `G` 编号和“访谈者强引导后的回答”。这类材料可以分析参与者明确补充的内容，但不能在报告中改写为参与者自发提出的经历或需求。

## 4.6 单一证据性质规则

一行只能有一种证据类型。如果同一段话同时包含具体事件、一般经验、事件后的自我报告或强引导回答，应拆成多行，并分别保留时间戳。不得使用“真实事件与一般经验”之类的混合证据类型来回避拆分。

## 5. 初始编码的命名规则

优先使用“对象或条件＋行为或变化”的结构：

- 网络访问中断；
- 家庭事务占用计划时间；
- 未完成任务顺延至次日；
- 在自然子任务边界暂停；
- 可见计算结果保留进度；
- 困倦时延后高要求任务。

每个编码尽量只表达一个中心意思。编码应回答“材料里发生了什么”，而不是“研究者认为这意味着什么”。

## 6. 禁止写入初始编码的内容

以下表述不能作为开放编码：

- 系统应该自动重新调度；
- 用户需要智能干预；
- 这是一个 JITAI 决策点；
- 系统提高了恢复效率；
- 用户属于低精力类型；
- 用户存在焦虑、拖延症或其他未经参与者明确报告的心理状态；
- 该设计一定能够降低认知负担。

这些内容分别属于设计推论、理论映射、效果判断或未经支持的推断。

## 7. 必须保持的概念边界

### 7.1 未开始不等于执行中断

计划中的任务从未开始、开始较晚或数日没有推进，不能写成“正在执行的任务被中断”。

### 7.2 暂停不等于恢复困难

参与者在自然边界休息并能直接继续时，应保留“恢复阻力低”或“不需要额外衔接”的边界证据。

### 7.3 延期不等于最终完成

参与者说“明天再做”只能编码为顺延或计划调整；没有后续证据时不能写成已经完成。

### 7.4 自报状态不等于系统推断

疲劳、疼痛、困倦、挫败或情绪变化只能在参与者明确表达时记录，并注明是自报。

### 7.5 暂时恢复不等于障碍解除

例如参与者找到临时网络完成部分工作，但回到原环境后仍然受阻，应分别记录“部分继续”和“障碍持续”。

### 7.6 假设偏好不等于使用证据

愿意尝试、认为可能有帮助或描述理想功能，不能用于声称系统已被接受或产生效果。

## 8. 试编码审查结论

根据 P01–P03 的16条记录，当前编码粒度可以继续使用，但后续必须坚持以下修正：

1. P01-E01 与 P02-R01 主要描述计划未推进，不能与 P03-E01 的执行中外部中断合并。
2. P01-C01、P01-C02 和 P02-C01继续作为相关背景记录，不升级为焦点事件。
3. 对同一时间范围拆出多行是允许的，但每行必须对应不同意义，并避免重复编码同一内容。
4. 使用“约”标记无法从逐字稿精确确定的边界，不进行虚假精确化。
5. 参与者明确报告“不需要复杂恢复”的材料必须保留，不能只收集支持系统设计的正向案例。
6. P04–P06 的复查表明，“包含任务内容”不足以判为具体事件；缺少单次情境锚点时必须标为一般经验。
7. `E`、`R`、`C`、`H`、`G` 编号只帮助追踪证据性质，不构成证据强弱排序。
8. P07–P09 的复查表明，访谈者提供核心情境后得到的材料需要独立标为 `G`，并且混合证据类型必须拆行。

## 9. 每批编码后的检查清单

- [ ] 每行能够追溯到参与者、事件和时间戳。
- [ ] 证据摘要没有姓名或其他不必要的可识别信息。
- [ ] 证据类型与片段性质一致。
- [ ] 每行只有一种证据类型；混合材料已经拆行。
- [ ] 初始编码描述材料，而非解释主题或提出设计。
- [ ] 没有把未开始、暂停、执行中断和延期混为一类。
- [ ] 没有把参与者的计划当作已经发生的结果。
- [ ] 没有把访谈者提示当作参与者自发观点。
- [ ] 保留了反例、无需求和低恢复阻力材料。
- [ ] 不确定处写入备忘录，而不是猜测补全。

## 10. 版本边界

本规则由 P01–P03 试编码形成 v0.1，经 P04–P06 修订为 v0.2，再经 P07–P09 修订为 v0.3。v0.3 新增 `G`（访谈者强引导后的回答），并禁止在同一行混合多种证据性质。下一次规则复查安排在 P10–P12 编码完成后；任何新增、合并或修改都必须记录版本变化，不得静默改写。
